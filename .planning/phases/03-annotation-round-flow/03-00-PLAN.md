  <name>Task 1: Write nginx.conf with security headers and SPA routing</name>
  <files>nginx.conf</files>

  <read_first>
    - .planning/phases/03-annotation-round-flow/03-CONTEXT.md — locked security headers, try_files pattern, server_tokens directive
    - vite.config.js — base: '/data-annotation/' is the exact location prefix to configure
  </read_first>

  <action>
    Create nginx.conf at the repo root. This file must exist before the Docker build runs
    because the Dockerfile COPY instruction copies it into the image. Write it first.

    Server block structure:
    - listen 8080 on all interfaces — nginx runs as non-root (uid 101) and cannot bind
      privileged port 80 without capabilities; 8080 is the correct port for a USER nginx container
    - server_name _ (catch-all)
    - server_tokens off — hides the nginx version from the Server response header
    - root /usr/share/nginx/html — document root matching where dist/ is copied
    - index index.html
    - Security headers added via add_header directives in the server block (applies to all locations):
      X-Frame-Options SAMEORIGIN always
      X-Content-Type-Options nosniff always
      X-XSS-Protection "1; mode=block" always
      Referrer-Policy strict-origin-when-cross-origin always
    - location /data-annotation/ block with try_files $uri $uri/ /data-annotation/index.html
      — this handles React client-side routing so that deep links (e.g. /data-annotation/review)
      return index.html instead of 404
    - location = / block redirecting to /data-annotation/ so that navigating to the root
      returns HTTP 301 to the app prefix (improves UX)
    - gzip on with gzip_types covering text/plain, text/css, application/javascript,
      application/json, image/svg+xml — reduces asset payload size

    Do not add TLS, rate limiting, or Content-Security-Policy — all are deferred per CONTEXT.md.
    Do not add client_max_body_size or proxy directives — this is a pure static file server.
    The "always" parameter on add_header ensures headers are sent on error responses too,
    not just 200 OK.
  </action>

  <verify>
    <automated>grep -c "listen 8080" nginx.conf && grep -c "server_tokens off" nginx.conf</automated>
  </verify>

  <action>
    Create Dockerfile at the repo root. Use two named stages: AS builder and AS production.

    Builder stage: FROM node:22-alpine AS builder. WORKDIR /app. COPY package*.json ./
    and RUN npm ci to install dependencies with the lockfile. Then COPY . . and RUN npm run build
    to produce dist/.

    Production stage: FROM nginx:1.27-alpine AS production. Remove the default nginx site config
    with RUN rm /etc/nginx/conf.d/default.conf. COPY nginx.conf /etc/nginx/conf.d/default.conf.
    COPY --from=builder /app/dist /usr/share/nginx/html. EXPOSE 8080. Add USER nginx as the
    final instruction — this sets the container's default user to nginx (uid 101) so that
    docker inspect --format='{{.Config.User}}' returns "nginx". The nginx:1.27-alpine image
    configures nginx to listen on port 8080 when running as a non-root user; the nginx.conf
    written in Task 1 uses listen 8080 to match.

    Create .dockerignore at the repo root. Exclude: node_modules, dist, .git, .planning,
    .github, coverage, *.log, .env*, .DS_Store. This keeps the build context small and prevents
    secrets or planning artifacts from entering the image layers.

    Do not add CMD — the base nginx:alpine image provides the correct default CMD.
    Do not inline any shell scripts or heredocs inside the Dockerfile action description.
    Reference identifiers only: stage names, image tags, COPY targets, RUN commands.

    After writing both files, run the build: docker build -t annotation-app:hardened .
    Then verify the image exists and run the container to confirm headers:
    docker run --rm -d -p 8080:8080 --name ann-test annotation-app:hardened
    sleep 2
    curl -sI http://localhost:8080/data-annotation/
    docker stop ann-test
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Build context → Docker daemon | Files from repo enter the image; .dockerignore controls what is excluded |
| Container → host port 8080 | HTTP traffic from browser enters nginx on port 8080 mapped to host 8080 |
| Client browser → nginx | All input is HTTP requests for static assets; no dynamic request handling |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | nginx Server header | mitigate | server_tokens off in nginx.conf hides version string |
| T-03-02 | Tampering | Clickjacking via iframe embedding | mitigate | X-Frame-Options: SAMEORIGIN header on all responses |
| T-03-03 | Tampering | MIME-type sniffing by browser | mitigate | X-Content-Type-Options: nosniff header on all responses |
| T-03-04 | Elevation of Privilege | Container running as root | mitigate | USER nginx in Dockerfile sets container user to nginx (uid 101); docker inspect --format='{{.Config.User}}' returns "nginx"; nginx listens on port 8080 (non-privileged) |
| T-03-05 | Information Disclosure | Build secrets in image layers | mitigate | .dockerignore excludes .env*, .planning, .git; multi-stage build ensures node_modules never enter production stage |
| T-03-06 | Tampering | CVEs in base image packages | mitigate | nginx:1.27-alpine has no perl-base, no curl; trivy scan gate enforces CRITICAL=0, HIGH=0 before ship |
| T-03-SC | Tampering | npm/pip/cargo package legitimacy | accept | No new npm packages added in this phase; only npm ci with existing locked package-lock.json runs inside builder stage |
